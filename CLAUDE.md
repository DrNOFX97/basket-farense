# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Web app (UI and docs in European Portuguese) with fixtures, results, standings and stats for every SC Farense basketball age group, sourced from the NBN23/Swish API used by the Portuguese Basketball Federation. See `README.md` for the full feature list and data limitations.

## Commands

```bash
python3 serve.py [--port 8790] [--host 127.0.0.1] [--no-live]   # local server on :8000 (Python 3.9+ stdlib only)
python3 build_data.py                                           # refetch API (cached in cache/) and rewrite data/farense.json
node scripts/check-views.mjs                                    # smoke test (also `npm run check`): every view × team × game against data/farense.json
for f in app/js/*.js app/js/views/*.js; do node --check "$f"; done   # syntax check
node scripts/check-live.mjs <email> <password>                  # exercise the Netlify live function without Netlify
node scripts/build-static.mjs                                   # build dist/ + netlify/lib/equipas.mjs
netlify deploy --prod --build                                   # deploy
```

There is no linter, bundler or unit-test framework; `check-views.mjs` is the only test and fails on empty HTML, `undefined`, `NaN` or `[object Object]` in rendered output. There is no single-test mode.

## Architecture

Two independent halves joined by `data/farense.json`:

- **Data pipeline (Python):** `swish_client.py` (GraphQL/Firebase login, token, on-disk response cache in `cache/`) → `build_data.py` (normalises into `data/farense.json`). Credentials come from `SWISH_EMAIL`/`SWISH_PASSWORD`, then `creds.txt`, then `~/.config/farense-basket/creds.txt`; the session token is cached outside the project. `cache/`, `dist/` and credentials are not versioned.
- **Frontend (`app/`):** no build step, native ES modules, hash routing (`#/época/escalão/vista`). `app.js` is shell + router, `data.js` loads the JSON and derives aggregates, `views/*.js` render one view each (resumo, jogos, jogo, classificacao, plantel, aovivo), `ui.js`/`format.js` are shared helpers. Design tokens and components live in the single `css/app.css`.

**Live mode exists twice and must stay in sync:** `live.py` (background thread polling the API every 4 s during a game / 25 s otherwise, served by `serve.py` at `/api/live`) and `netlify/functions/live.mjs` (stateless equivalent). Netlify redirects `/api/live` to the function and needs `SWISH_EMAIL`/`SWISH_PASSWORD` env vars. `netlify/lib/equipas.mjs` is generated by `scripts/build-static.mjs` from the JSON — do not hand-edit.

## Gotchas

- The source has **no missed field goals, rebounds, assists, steals, blocks or turnovers** (always zero), so field-goal percentage is impossible. Views show only made 2/3-pointers and free throws as made/attempted; keep it that way and keep the on-screen disclaimer.
- API timestamps end in `Z` but are the venue's local time. Parse the components from the text; never convert time zones.
- `.planning/` holds GSD project docs (PROJECT, ROADMAP, UI-SPEC, phase summaries) with design rationale.
